# Live validation — 28 October 2026

These results come from a private Cloudflare deployment using two domains and four explicit addresses. Domain names, login identities, resource IDs, and recovery snapshots are intentionally omitted from the public repository. All messages were exchanged between addresses controlled by the operator.

## Verified behavior

- CLI provisioning of the Worker hostname, D1, private R2, jobs and dead-letter queues, Access application/policy, and restricted Cloudflare identity provider.
- Reuse of an existing domain's mail configuration and onboarding of a second domain, with unrelated routes preserved.
- Receipt and indexing of four test messages with attachments, one at each configured address.
- Cloudflare Access login followed by an authenticated mailbox view.
- Browser reply with the original receiving address retained as sender; provider acceptance and receipt in the destination inbox.
- Browser forwarding with a copied attachment; provider acceptance and receipt in the destination inbox.
- Sanitized formatted email and blocked remote-image placeholders.
- Access login redirects for unsigned and forged-header requests to bootstrap, export, attachment, and client asset paths.
- Ownership-aware CLI diagnostics, catch-all support with an explicit recipient registry, and the security update's deployment.
- R2 managed public access disabled and no public custom bucket domains during the security review.

## Limits of this validation

Optional delivery-event subscriptions were not configured. Outbound copies showed `accepted`; receipt in the other controlled inbox independently established delivery for the tested messages.

A second unauthorized human login, maximum-size messages, large-volume load, actual quota exhaustion, provider outages, and destructive live cleanup were not exercised. Local synthetic tests cover many related failure cases, but must not be represented as successful live tests.

Private configuration, ownership journals, Access credentials, mail, and before/after DNS snapshots remain outside the repository. See [local validation](local.md), [security remediation](../security/remediation-2026-10-28.md), and the [deployment guide](../deployment.md).
